# 42 — Tier 1 update 3 synthesis: completed evidence, corrections, and promotion boundaries

**Scope.** This decision record incorporates the updated NNUE ceiling report, the prior master synthesis, and completed reports **32–41**. It is a synthesis of their recorded inspections, binary runs, failures, and designs; it does **not** rerun a test, retrain a model, add code, or create a candidate. Where a report says a result was only recorded from an unavailable artifact, that limitation remains attached to the result here.

> **Disposition: preserve shipped defaults and do not promote a mechanism from this update.** The new work adds useful negative evidence, verifies several current implementation states, and identifies a small number of bounded future projects. It supplies no completed strength test, no new NNUE candidate, and no authorization for Tier 2 or Tier 3 work.

> **Evidence rule.** A source inspection establishes only the inspected code state. A release-binary smoke establishes only the stated execution path on that binary and fixture. A blocked Cargo command is a negative environment result, not a passing test. A design, external precedent, static score, search NPS, or fixed-position result is not Elo evidence. A game-facing default requires a provenance-complete, real paired-game SPRT for that exact candidate and configuration.[1]

## Executive update

1. **The NNUE piece-count intervention thread is closed at the tested data scale.** The real paired-label measurement retires the older simulated 50–56 cp noise-floor premise: the reported fresh-replay labels differ by **17–22 cp MAE** with Pearson **0.93–0.98**. Hard resampling improved four of seven rare/mid buckets but regressed the two common buckets that account for 57% of real games; clipped soft reweighting made bucket 2 19.5% worse, with rare pools of only 44 and 1,030 examples out of 98,000. Those quoted experiment figures were verified by the updated report against supplied pasted evidence, **not recomputed in this checkout**.[2] This closes further piece-count resampling/reweighting variants at this scale. It does not prove a capacity ceiling, a broad coverage diagnosis, or a retraining benefit.
2. **Several apparent features are confirmed absent, while two common “partial support” readings are rejected.** There is no local Syzygy integration or data, no pondering state or `Ponder` option, no generalized Chess960 representation, no integrated fixed-search bench, no NNUE quantized runtime, and no Hash auto-sizing.[3][4][5][6][7][8] An ignored `go ponder` token is not pondering; accepting an orthodox rights field on a Chess960-like board is not Chess960 support; and a Python Syzygy client without table files is not a runnable tablebase probe.
3. **Existing implementation is more specific than several broad claims suggest.** Lazy SMP already uses the `1,2,3,1,2,3,…` helper start-depth cycle; current NNUE inference is float32 with source-gated AVX2/FMA dispatch; Contempt is a context-dependent search draw score, not a direct static-evaluation bonus; and Hash is a fixed 128 MiB default with explicit resize/clear lifecycle.[8][9][10][11]
4. **The local build evidence is weaker than a generic “tests blocked by lockfile v4” shorthand.** Cargo 1.75 first rejects the v4 lockfile. In the AVX2 audit, temporarily removing that lockfile from the build path (and restoring it) reached separate Rust-version errors for `usize::is_multiple_of` in unrelated workspace files. Thus a fresh workspace compile/test pass remains unverified for both reasons; no report may call it a pass.[11]
5. **The immediate common need remains measurement and provenance, not speculative engine changes.** A compatible Rust environment, exact node-limit observability, a fixed reproducible bench, and bounded default-off instrumentation would make later work falsifiable. They do not themselves demonstrate strength. The existing real binary runs are useful smoke checks but include heterogeneous HCE/NNUE configurations and must not be pooled as one performance baseline.[1][7][11]

## Closed NNUE ceiling thread: precise disposition

The update changes the prior master synthesis in one important way. The master correctly elevated effective reachable-position coverage over the obsolete label-noise premise and proposed a matched coverage/capacity diagnostic.[1] The subsequent NNUE update supplies two intervention outcomes for one narrow axis: **piece-count-bucket hard resampling and clipped inverse-frequency soft reweighting**. Their documented trade-offs fail the supplied predeclared intent at the available 98,000-example scale, so that axis is now **closed**.[2]

This closure is deliberately narrow and should not be misreported as an explanation of the entire performance gap:

* It **does close** more variants of the same piece-count resampling/reweighting idea at this data scale.
* It **does retire** the old simulated 50–56 cp label-noise-floor explanation at the tested paired-label scale.
* It **does not establish** that v4 lacks capacity, that raw data will solve the gap, that a wider architecture will help, that labels are correct, or that broad reachable coverage has been measured.
* It **does not authorize** a 178M/500M same-distribution retrain, a `Full_Threats` switch, a width/depth change, cloud spend, model export, or default change.

Only if complete state/source/teacher provenance becomes available may a *different* conditional diagnostic be considered: equal-record and equal-optimization current-versus-narrower capacity on random-versus-coverage-balanced, game-disjoint data, with predeclared per-stratum held-out rules. Approximate record identity must not be called legal-position deduplication. Even a positive offline result remains below candidate training/export/parity/smoke and real paired-game SPRT gates.[1][2]

## Explicit Tier 2 and Tier 3 boundaries

The labels below are boundaries, not work authorization. They prevent a proposal or a binary smoke from being quietly reclassified as implemented or validated.

| Boundary | Starts only when | Permitted scope | Explicit exclusions / promotion requirement |
|---|---|---|---|
| **Tier 1 — current and possible next evidence work** | A separate owner and approval exist for research, compatible-toolchain restoration, or default-preserving observability/measurement. | Source inspection, reproducible fixtures, a standalone fixed bench, exact-node contract tests, default-off counters, offline provenance checks, and specified no-change smoke tests. | No candidate feature/model/default, cloud/self-play scale, game campaign, acquisition/hosting, commit, or push follows automatically. A fixed test can reject a candidate but cannot establish Elo. |
| **Tier 2 — bounded prototype/implementation** | A written contract, narrow owner, acceptance fixtures, disabled/default equivalence where relevant, and prerequisite Tier 1 evidence exist. | Examples: opt-in tablebase adapter (without acquiring/hosting collections); default-false ponder lifecycle; quantized NNUE prototype after parity/benchmark gates; default-off Chess960 correctness prototype; conservative Hash auto-sizing prototype; or an isolated pawn/SMP/Contempt behavior candidate. | Tier 2 is not deployment, a strength claim, or a default flip. It may not bypass missing provenance, legal-state, numerical-parity, race, low-memory, or protocol tests. |
| **Tier 3 — scale, interoperability, campaign, or promotion validation** | A bounded Tier 2 candidate has passed its deterministic/offline/fixed-position gates and a complete immutable run specification is approved. | Examples: tablebase file acquisition, packaging, mirroring, or hosting; broad Chess960 reference/GUI interoperability and stability; NNUE training/self-play at scale; and real paired-game validation/campaigns. | Preserve binary/model/options/book/opening/hardware/time-control provenance and raw logs/PGNs. A candidate changes a game-facing default only after the declared paired-game SPRT supports that exact claim; incomplete, interrupted, or unrelated matches do not promote it.[1] |

Across all streams, **Tier 3 is also the boundary for a strength/default conclusion**. A tablebase correctness suite, quantization parity result, UCI protocol smoke, memory-pressure run, or static evaluation corpus can support Tier 2 continuation or reject a candidate; it cannot replace paired real-game evidence. Tablebase data distribution is specifically Tier 3 even if an opt-in adapter has been implemented, and full Chess960 interoperability/variant validation is specifically Tier 3 even if a parser/move generator prototype exists.[3][7]

## Coordinated next decisions

1. **Do not reopen closed NNUE piece-count sampling.** If NNUE work returns, require the separate provenance-complete diagnostic specified above; otherwise redirect effort to measurable infrastructure.
2. **Restore a compatible test environment before treating source changes as validated.** Document the toolchain and preserve the lockfile; do not alter source or lockfile merely to turn an environment limitation into a green result. The two observed blockers must both be addressed or reported.
3. **Prioritize shared Tier 1 measurement hygiene.** An exact node-limit acceptance test and a developer-only fixed bench with explicit NNUE/HCE status, aggregate monotonic timing, final node accounting, configuration manifest, and separate node-signature/NPS interpretation would serve multiple later investigations.[1][8]
4. **Keep feature candidates isolated.** Tablebase, ponder, quantization, Chess960, pawn terms, Lazy SMP changes, and auto-sized Hash have materially different state, concurrency, resource, and protocol risks. Do not bundle them or import foreign constants as defaults.
5. **Preserve defaults pending the proper gate.** This includes the shipped NNUE, float32 NNUE format, 128 MiB Hash, current Lazy SMP staggering, Contempt 25, and no Ponder/Chess960/Syzygy/bench behavior. The absence of a feature is not a reason to rush an unmeasured implementation.
