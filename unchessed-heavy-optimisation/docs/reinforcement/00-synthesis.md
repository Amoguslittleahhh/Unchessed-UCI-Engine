# Reinforcement investigations — synthesis, implementation order, and gates

**Scope.** This synthesis reconciles investigations 01–05 for `/home/ubuntu/Unchessed-UCI-Engine` at `manus/rustc-bootstrap-trial` / `818ef9d`. The repository worktree was clean when this review was made; this report is the only artifact written. The central distinction is deliberate:

> **Implement now** means an isolated correctness, provenance, diagnostic, or default-off observability change can be authored without unavailable training assets. It does **not** mean that a game-facing behavior, a trained model, or an Elo claim is ready. A change is promotable only after the evidence in its row is complete.

The current sandbox has `rustc/cargo 1.75.0`, which cannot read the repository’s lockfile v4, lacks PyTorch, lacks the real NNUE corpus/sidecars and Unarchitectured checkpoints/shards, and lacks the configured cutechess/book environment. The shipped NNUE and deployed `.unmetal` package are present; neither substitutes for the missing original-position/training assets. These are distinct blockers, not interchangeable reasons to weaken a test.

## Implementation order

### Phase 0 — restore the verification floor before accepting Rust changes

Provision the repository-requested current stable Rust toolchain and run `cargo test --workspace --release` (with focused search/persona/Unarchitectured filters as appropriate). Do not accept a Rust-side change merely because Python structural tests pass: the current `cargo 1.75.0` lockfile failure means no fresh local Rust compilation was established for persona or Unarchitectured work. Independently provision the real match host only for later strength gates: pinned engine binaries, opening book, `cutechess-cli`, CPU/threads/hash/time-control recording, and raw PGN/log retention. This phase is a **test-environment prerequisite**, not a reason to defer safe source implementation.

### Phase 1 — implement isolated correctness, observability, and provenance protections

These items preserve normal defaults and can proceed in parallel once ownership avoids overlapping files. Within each lane, retain the listed order.

1. **Search correctness first:** split node-budget checking from the 2,048-node time/stop poll so an explicit `go nodes N` stops at `N` (or at most one node beyond), while no-node-limit searches retain the old cadence. This is a public UCI contract fix, not an Elo hypothesis. [Search][S]
2. **Add search observability before search tuning:** add opt-in `SearchStats` with invariant checks and no disabled-path output/tree change. Only then parameterize the hard-coded reverse-futility cap as `RFPMaxDepth`, retaining the legacy default `6`; candidates other than `6` wait for Phase 4. [Search][S]
3. **Make NNUE data handling fail closed:** first replace all-record/list processing with bounded streams and refuse output/input aliases; then add atomic destination publishing and fresh `verify`; then implement structural validation, versioned source/score/teacher manifests, and ordered-record binding. Add the state companion to future generation now, but do not pretend that it restores state already discarded from old records. [NNUE][N]
4. **Make persona data measurable, not persuasive:** add `AdapterTelemetry=false`, game/decision/observation IDs, side-effect-free model snapshots, and a strict offline parser plus runner-owned JSONL manifest. In the same measurement lane, repair `elo_detector.py` so legacy and V2 semantics, difficulty weights, and book behavior are explicit and golden-tested against Rust snapshots. Do not alter `PersonaSmooth=false` or `EngineDetectV2=false`. [Persona][P]
5. **Add the oracle diagnostic surface only:** implement a separate `analyse_oracle_rating_conditioning.py` that validates paths before importing Torch, accepts only the legacy oracle checkpoint format, and writes provenance-complete JSON. It must not overload the student package analyzer or use an NNUE, exported student, or dual-Elo checkpoint as a substitute. [Oracle][O]
6. **Unarchitectured housekeeping only:** optionally correct the stale package-loader comment, preserving the runtime and all existing gates. Do not write a speculative larger-GAB schema, int8-activation kernel, package converter, or post-hoc weight clamp. [Unarchitectured][U]

### Phase 2 — satisfy provenance and diagnostic gates before spending on candidates

1. **NNUE asset preflight:** obtain immutable source-shard manifests/files, a complete canonical-state companion *or* an auditable regeneration that reproduces each authoritative 104-byte shard SHA-256, a declared teacher binary/checkpoint/configuration, sufficient free space, and non-colliding outputs. High-node search labels are prohibited until the source hash reconstruction succeeds. A bitboard-only old shard can support only an explicitly labelled static-forward experiment, not legal-move search relabeling. [NNUE][N]
2. **Oracle causal-location diagnostic:** on a trusted Torch-capable host with the original legacy checkpoint, execute the fixed 200-position/seven-rating inference sweep. Its result selects the next Unarchitectured research branch: a material oracle response supports student-path/distillation investigation; negligible oracle movement pushes work upstream to oracle architecture/training. This is an **offline diagnostic**, not a strength result. [Oracle][O]
3. **Persona measurement corpus:** run a telemetry-disabled/enabled smoke pair, then a `cutechess -debug` diagnostic run (initially concurrency 1), preserving telemetry, manifest, and PGN. Collect a pre-registered labelled matrix that separates `expected_suspect` policy truth from generic engine origin and separates metadata-assisted from anonymous cases. [Persona][P]

### Phase 3 — only now create controlled candidates

* Generate bound NNUE labels, independently verify each output, freeze an immutable old/new split, retrain with a complete v4 run manifest, and validate export through Rust loading. A lower MAE or higher label disagreement is not a promotion result. [NNUE][N]
* For Unarchitectured work, acquire trusted train/calibration/holdout shards plus oracle/student checkpoint and train the four-arm matrix: baseline; wider 32/64/64 GAB; current GAB plus target-scheme QAT; wider GAB plus QAT. Select by validation, calibrate, export, and only then make a candidate-tested runtime compatibility update. Int8 activations remain a retraining hypothesis because all five frozen-model schemes miss the `5e-3` parity gate. [Unarchitectured][U]
* For search, run one non-legacy `RFPMaxDepth` or one pruning candidate at a time, only after its deterministic fixtures and telemetry establish intended activation/safety. Do not bundle heuristics or import another engine’s constants. [Search][S]

### Phase 4 — promotion gates are separate from all prior tests

First use reject-only smoke screens where available; a pass means only “not obviously catastrophic.” Then use a real paired cutechess/pentanomial SPRT on the declared hardware, with raw PGN/logs and immutable binary/model/book hashes. The search convention is `Threads=1`, fixed hash/book/current evaluator, `elo0=0`, `elo1=5`, `alpha=beta=0.05`; NNUE requires explicit Adaptive-on persona and Adaptive-off eval-only gates; Unarchitectured must specify the tested hint exit rather than silently use `2/128`. No simulation, MAE, diagnostic sweep, fixed-position parity result, or interrupted match crosses this gate.

## Non-negotiable evidence rules

1. **Default preservation is an assertion, not an intention.** Default-off output and fixed-depth tree equivalence must be tested for telemetry/parameterization, and UCI defaults must remain explicit.
2. **Provenance precedes scale.** NNUE labels must be cryptographically tied to the exact ordered boards *and full replayable state*; an equal record count is inadequate.
3. **Parity precedes optimization.** A generic `UNARCHV1` container parsing a candidate does not prove the fixed Rust runtime can forward it correctly. Do not weaken the independent `5e-3` full-exit or `5e-4` integer-path gates.
4. **Observation precedes behavioural claims.** Persona telemetry requires external truth labels and coverage accounting; simulated flip rates and unlabelled prose logs cannot measure live detector accuracy.
5. **SPRT precedes strength/default claims.** Unit tests, CPU diagnostics, package integrity, label MAE, or an interrupted/non-paired match cannot authorize a live default change.
