# 31 — Tier 1 master synthesis: evidence, diagnostics, and promotion boundaries

**Scope.** This report synthesizes the completed reinforcement investigations in [`00-synthesis.md`](00-synthesis.md) through [`30-continuous-sprt.md`](30-continuous-sprt.md), with particular attention to the completed Tier 1 reports `13`–`30`. It is a decision record, not a candidate result. It distinguishes repository/source inspection, previously recorded measurements, proposed diagnostics, and promotion evidence.

> **Master disposition: preserve all shipped defaults; restore measurement and provenance before scale.** The review identifies several cheap, falsifiable diagnostics and a small number of default-preserving correctness/protocol changes worth planning. It does **not** establish a strength gain, authorize a model replacement, or justify a tree-changing search default.

> **Tier boundary.** No Tier 2/3 **engine feature, NNUE retraining, chess self-play/MCTS, candidate match campaign, cloud job, paid compute spend, default change, commit, or push** began in the `13`–`30` investigations. Report `12` is an already-completed, bounded **Tier 2.2 toy** replay/value-learning plumbing calibration; it was explicitly not chess, did not load NNUE, and did not resolve the architecture or throughput gates for RL. It must not be represented as Tier 2/3 chess implementation or compute. The research/design recommendations below do not automatically start a later tier.

## Executive conclusions

1. **The NNUE label-noise premise was corrected.** The real, same-position PGN-replay measurement found **17.41–21.99 cp MAE** and **0.929–0.983 Pearson correlation** between the incumbent 5,000-node HCE label and a 50,000/100,000-node comparison search, across four sources and **2,900 paired positions**. It invalidates the prior *assumed* 50–56 cp noise-floor argument at the tested scale. It does not prove that the deeper label is correct, that archived 108M records can be relabelled, or that a retrained net would gain Elo. [`08`](08-label-noise.md)
2. **Effective reachable-position coverage is now the leading NNUE hypothesis, not established capacity exhaustion or label noise.** More records helped the v4 family but with diminishing returns; the proper next test is a matched coverage-versus-capacity matrix on game-disjoint data, not a blind wider net or another large same-distribution retrain. Existing-corpus deep-search relabelling remains blocked by missing complete state, source shards/sidecars, and binding provenance. [`13`](13-nnue-ceiling.md), [`02`](02-nnue.md)
3. **RL remains independently blocked by both architecture and throughput.** The shipped `HalfKAv2_hm` NNUE is a scalar alpha-beta evaluator, not a policy/value network; the repository has no verified chess MCTS/PUCT, legal-action policy ABI, replay/self-play stack, or measured NNUE batch-inference throughput. The toy calibration in report `12` only verified deterministic toy plumbing and does not relax either blocker. Do not substitute the unrelated 9.72 ms Unarchitectured timing for NNUE throughput. [`06`](06-rl-selfplay.md), [`12`](12-tier2-calibration.md)
4. **Most proposed search additions are either already present, overlapping, or unmeasured.** Check extension and strict negative-SEE qsearch pruning are already implemented; the null-move NNUE accumulator design shows no confirmed bug. Multi-cut, IIR, razoring, and LMP are speculative selective layers atop an already selective search and should remain deferred absent opportunity telemetry and tactical safety evidence. One-ply quiet countermove history is the most credible new ordering-only diagnostic, but it too has no local benefit measurement. [`14`](14-check-extensions.md)–[`23`](23-multipv-aspiration.md)
5. **Protocol/correctness work is more defensible than speculative strength work.** Exact `go nodes N`, default-off `SearchStats`, future-safe NNUE data tooling, persona telemetry/provenance, and bounded UCI features have clear acceptance tests. `searchmoves`/`go mate`, default-zero `Move Overhead`, and a narrowly scoped rules-draw detector are protocol/correctness candidates, not Elo claims. [`00`](00-synthesis.md), [`24`](24-uci-searchmoves-mate.md)–[`28`](28-dead-position-draws.md)
6. **Every game-reachable candidate remains independently SPRT-gated.** Offline metrics, historical source inspection, toy calibration, static parity, fixed-position safety, node counts, a smoke screen, or an interrupted match cannot promote a default. A real paired-game test must freeze binary/model/options/book/hardware/time-control provenance and retain raw PGN/logs. [`00`](00-synthesis.md), [`30`](30-continuous-sprt.md)

## Recommendations and ordering

### 1. Preserve incumbents and define non-negotiable gates

Keep the current search defaults, `PersonaSmooth=false`, `EngineDetectV2=false`, `UnarchitecturedHint=false`, and the shipped NNUE. Maintain the current retained i8-weight/i16-activation Unarchitectured path. Do not relabel flattened archival records with invented state, use a model file as a label sidecar, copy foreign search/king-safety constants, or report a score transform as calibrated WDL.

For any game-reachable candidate, preserve immutable binary and model hashes; evaluator/options/threads/hash/book/time control/hardware; paired opening identities; raw PGNs/logs; completed test status; and the exact sequential-test parameters. The project convention remains a paired test with declared `elo0`, `elo1`, alpha, beta, and a result that is explicitly upper-bound, lower-bound, or inconclusive. [`00`](00-synthesis.md), [`30`](30-continuous-sprt.md)

### 2. Build the common observability and provenance floor before feature selection

The highest-value near-term work is not another selective rule. It is exact node-limit enforcement, disabled-path-verified search telemetry, future-safe NNUE label/data provenance, and persona telemetry/manifest integrity. These tools make later work falsifiable and prevent accidental corruption, lost labels, or behavioural assertions without truth data. They should retain old output and search behavior when disabled and be accepted only with explicit equivalence tests. [`00`](00-synthesis.md), [`01`](01-search.md), [`02`](02-nnue.md), [`03`](03-persona.md)

### 3. Treat NNUE research as a coverage and provenance question before a compute question

The corrected label result shifts the immediate diagnostic priority toward reachable coverage, distribution mismatch, and representation—not toward automatic high-node relabelling or a larger net. First obtain cryptographically bound source/state/teacher assets or an auditable exact regeneration. Then compare equal-record, equal-optimization random and coverage-balanced samples, with game-disjoint held-out strata and a matched narrow/current capacity test. A lower MAE, high correlation, or a smoke pass remains insufficient for model replacement. [`08`](08-label-noise.md), [`13`](13-nnue-ceiling.md)

### 4. Keep RL deferred until *both* independent gates pass

RL must not be reframed as merely an asset or compute shortage. It needs (a) a new chess policy/value architecture, legal-action encoding/masking, MCTS/PUCT, replay, and promotion/evaluation design, and (b) measured NNUE batch and tree-search throughput sufficient for a bounded real chess prototype. The scalar evaluator and a toy value learner do not supply either condition. The initial viable experiment, if later approved, is a deterministic offline interface/throughput test—not a cloud self-play run. [`06`](06-rl-selfplay.md), [`12`](12-tier2-calibration.md)

### 5. Prefer protocol correctness and order-only measurement over compounded forward pruning

`searchmoves`, `go mate`, and default-zero `Move Overhead` have concrete UCI contracts and can be implemented as bounded correctness work after approval and tests. `UCI_AnalyseMode` should wait for a demonstrated GUI need. For search strength research, first measure existing mechanisms; check extensions and qsearch SEE pruning should be audited rather than duplicated. Of the new ideas, one-ply countermove history is the most coherent isolated ordering diagnostic; IIR, multi-cut, razoring, and LMP should not advance without demonstrated nonredundant opportunity. [`14`](14-check-extensions.md)–[`26`](26-uci-analyse-mode.md)

### 6. Keep infrastructure independent from a campaign

A continuous SPRT service can improve provenance and reproducibility but must begin as a private, self-hosted dry run with immutable manifests and server-side pair/statistic recomputation. It is not approval to start candidate testing or an automated promotion mechanism. Similarly, TT aging should start with an inbound-UCI lifecycle trace; explicit `ucinewgame` currently clears the TT, and universal boundary delivery is not yet measured. [`29`](29-tt-aging.md), [`30`](30-continuous-sprt.md)

## Status statement

This synthesis records completed research and designs only. **No new Tier 2/3 engine implementation, chess self-play or training computation, model candidate, match campaign, cloud job, paid compute spend, default change, commit, or push was begun by the `13`–`30` Tier 1 reports or by this synthesis.** The already-recorded report `12` remains accurately scoped as a bounded Tier 2.2 **non-chess toy** calibration artifact, not evidence that RL architecture, NNUE throughput, or Tier 3 chess work has begun.

The immediate strategic lesson is not “do more search” or “buy more compute.” It is to establish provenance, observability, exact protocol behavior, and falsifiable offline gates first; then permit at most one isolated candidate at a time, with the real paired-game SPRT retained as the only promotion gate for game-facing strength/default claims.
