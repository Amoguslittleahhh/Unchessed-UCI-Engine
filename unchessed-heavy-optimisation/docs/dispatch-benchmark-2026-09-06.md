# Universal-dispatch benchmark report — 2026-09-06

## Scope

This report evaluates the centralized CPU capability registry and the NNUE AVX2/FMA and AArch64 NEON paths. The scalar comparison is controlled by `UNCHESSED_DISABLE_SIMD=1`, which forces all optional kernels to use their scalar reference implementations. Every run uses the same release source, deterministic v1 `UNCHNNUE` fixture, one search thread, 4/16/64 MiB hash, four fixed positions, and completed UCI node-limited searches.

The benchmark harness is `scripts/benchmark-dispatch.py`; the deterministic evaluator fixture is generated by `scripts/make-benchmark-nnue.py`; raw CSVs are stored under `benchmarks/results/`.

## Native x86-64 results

The sandbox host is an Intel Xeon x86-64 machine with AVX2 and FMA. Three repeats were run for each of four positions and three hash sizes, producing 36 scalar and 36 dispatch measurements. Aggregate median NPS was **750,994** for scalar fallback and **1,328,394** for runtime dispatch, a **+76.88%** throughput difference.

## x86-64-v3 results

A separate build used `RUSTFLAGS='-C target-cpu=x86-64-v3'` and two repeats per condition. Aggregate median NPS was **767,262** for scalar fallback and **1,342,574** for runtime dispatch, a **+74.98%** difference. The per-position results are in `benchmarks/results/dispatch-v3.summary.md`.

The native and x86-64-v3 binaries were executed on the same host, so this is a build-target comparison rather than a comparison between physical hardware models. It should not be generalized to all x86-64-v3 CPUs.

## ARM and Apple Silicon validation

The following targets were installed and passed `cargo check --workspace`:

| Target | Result | Runtime benchmark status |
|---|---|---|
| `aarch64-unknown-linux-gnu` | Passed | Not executable on this x86 host; no QEMU runner installed |
| `aarch64-apple-darwin` | Passed | Compile-only; no Apple Silicon hardware available |

The capability registry reports NEON for AArch64 and identifies Apple Silicon for `aarch64-apple-darwin`. The NNUE runtime includes AArch64 NEON implementations for accumulator add/subtract and SCReLU/CReLU dot products. On AArch64, NEON is treated as part of the supported baseline rather than dynamically probed. Scalar fallback remains available through `UNCHESSED_DISABLE_SIMD=1`.

## Correctness validation

The native core test suite passed **132 tests**, with 0 failures and 6 existing ignored tests. The release workspace build passed. Both AArch64 cross-target workspace checks passed after the NEON implementation was added. The benchmark harness validates completed searches by waiting for `bestmove`; partial `info` lines are not accepted as completed measurements.

A real Apple Silicon benchmark remains necessary to measure the NEON implementation’s speed and floating-point behavior on M-series microarchitectures. The current results prove compilation and dispatch structure, not native ARM performance.

## Reproduction

```bash
python3 scripts/make-benchmark-nnue.py benchmarks/artifacts/benchmark-v1.unchnnue
cargo build --workspace --release
python3 scripts/benchmark-dispatch.py \
  --binary target/release/unchessed-adapter \
  --output benchmarks/results/dispatch-native.csv \
  --label native-dispatch --nodes 500000 --repeats 3 --hash 4 16 64
python3 scripts/benchmark-dispatch.py \
  --binary target/release/unchessed-adapter \
  --output benchmarks/results/dispatch-scalar.csv \
  --label native-scalar --scalar --nodes 500000 --repeats 3 --hash 4 16 64
```

For the x86-64-v3 build, add `RUSTFLAGS='-C target-cpu=x86-64-v3'` and use a separate target directory. The source and benchmark settings must remain identical when comparing results.
